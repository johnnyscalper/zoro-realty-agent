# 상담 에이전트 오프라인 평가

이 평가는 **개발용 규칙 모드와 실제 HTTP 도구 연결**을 검사합니다. 20개를 모두 통과해도 실제 Zoro의 자연어 이해 능력, 모델 추론 품질, 제공자 호환성 또는 실제 국토부 인증 성공을 검증한 것이 아닙니다. 실제 모델 서버·모델 식별자는 제공되지 않았습니다.

프로젝트 폴더에서 실행합니다.

```bash
python scripts/evaluate_agent.py
```

앱의 기본 의존성만 필요합니다. 추가 평가 패키지나 GPU가 필요하지 않습니다. 테스트 환경에서는 같은 20개 사례를 개별적으로 실행할 수 있습니다.

```bash
python -m pytest tests/test_agent_scenarios.py -q
```

각 사례는 새 임시 SQLite 데이터베이스, 명시적 가짜 Settings, 별도 세션을 사용합니다. `.env`를 읽는 기본 앱 초기화도 import 전에 차단합니다. 실제 소켓·HTTP 네트워크 전송은 금지되며 실패 시 평가 실패로 기록합니다. A15·A16만 가짜 키와 주입한 `httpx.MockTransport`를 통해 실제 국토부 요청 생성·XML 파서 경로를 검사합니다. 그 응답은 저장소의 가상 XML이며 내려받은 실거래 기록이 아닙니다.

평가 결과는 `reports/agent-development-evaluation.json`에 저장됩니다. 성공·실패 수와 고정된 검사 식별자만 기록하며 대화 전문, 원문 응답, 키, URL, 원문 예외, 개인 DB는 넣지 않습니다. `reports/`는 ZIP 배포 대상에서 제외됩니다. 실패가 하나라도 있으면 명령의 종료 코드는 1입니다. `--report-name NAME.json`으로 reports 내 파일명을 지정할 수 있습니다.

| 사례 | 확인하는 동작 |
|---|---|
| A01 | 예산을 추정하지 않고 질문 |
| A02 | 필수 조건 승인, 소음 선호와 제외 조건 분리, 면적·가격 경계 |
| A03 | 미확인 무단차를 확인 필요로 유지, 필수 확인 요청 최대 2개 |
| A04 | 엘리베이터와 무단차 독립 판단 |
| A05 | 계약 완료 변경 승인 및 후보 제외 |
| A06 | 현장 확인 승인·기록·후보 재검사 |
| A07 | 조건 변경 취소 후 업무 상태 보존 |
| A08 | 예산만 바꿀 때 나머지 조건 보존 |
| A09 | 후보가 없어도 필수 조건 자동 완화 금지 |
| A10 | 입주 지연 승인, 충돌 표시, 제공된 슬롯으로 대안 생성 |
| A11 | 첫 일정안 선택 후 별도 승인하여 내부 일정 반영 |
| A12 | 제공된 슬롯이 없으면 대안 없음 |
| A13 | 수동 상태 변경 후 오래된 일정 승인 거절 |
| A14 | 샘플 과거 전월세 출처·가상 표지와 매물 분리 |
| A15 | 모의 실거래 경로, 취소 매매 제외, 매물 상태 보존 |
| A16 | 외부 오류를 샘플로 대체하지 않음, 키 비노출 |
| A17 | 비허용 도구 반환을 실행하지 않음 |
| A18 | 같은 요청 및 승인 ID 중복 처리 방지 |
| A19 | 개발 모드 표시와 미설정 Zoro 거절, 자동 대체 없음 |
| A20 | 저장된 예산 질문에 `9억`으로 답하고 승인 후 검색 |

사례 정의는 `data/agent_scenarios.json`, 실행 로직은 `scripts/evaluate_agent.py`입니다. 기존 `data/scenarios.json`의 계획 자료와 별개이며, 테스트 결과를 자료 파일 자체에 덮어쓰지 않습니다. HTTP 응답, 저장된 세션, 승인 전후의 업무 상태, 출처 필드, 재전송 결과를 검증합니다. A17만 오케스트레이터의 개발 플래너 반환값에 비허용 도구를 주입하며 나머지 사례는 실제 개발 플래너를 사용합니다.

A15에서 `source: molit`, `synthetic: false`는 앱의 live 처리 경로가 보존하는 출처 표지입니다. **이 평가 전체는 여전히 가상·오프라인입니다.** 모의 전송으로 얻은 이 표지를 실제 국토부 응답 또는 인증 성공의 증거로 제시하면 안 됩니다. 보고서는 `live_molit_authenticated: false`를 명시합니다.

실제 Zoro 평가는 이 명령에서 제공하지 않습니다. `--mode`는 `development`만 허용하며 `.env`에 모델 설정이 있어도 읽거나 호출하지 않습니다. 실제 평가를 추가하려면 인터페이스·모델 ID·서버 설정 확인, 별도 명시적 실행 동의, 모델 전용 실행 경로 및 결과 표지가 필요합니다. 개발용 평가 점수를 실제 Zoro 점수로 바꾸어 보고해서는 안 됩니다. 실제 모델 연결 안내는 `ZORO_CONNECTION.md`를 참고하세요.
