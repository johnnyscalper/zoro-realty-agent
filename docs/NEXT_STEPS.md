# 다음 작업 — v0.4 이후

상담 대화·기존 도구 연결·후보 재검증·일정 복구·모델 어댑터·오프라인 평가까지 통합했습니다. 사용자 Windows PC의 두 국토부 API는 정상 표시됐다는 확인을 받았습니다. 기존 키를 다시 신청하거나 새 프로젝트를 만들 필요는 없습니다.

## 1. 새 버전으로 시연 흐름 익히기

`START_HERE_KO.md`의 네 개 예시 버튼으로 조건 저장 → 확인 결과 반영 → 입주 지연 대안 → 과거 실거래를 실행하세요. 각 변경의 승인·취소와 자료 출처를 보여주는 것이 핵심입니다. 현재 개발용 규칙 시연임을 표시하세요.

## 2. 행사 GPU 정보 받기

주최 측에서 서버 접속 방법, 모델이 이미 설치돼 있는지, 추론 서버 주소, 정확한 모델 ID, 인증 방식, 요청·응답 규격을 받습니다. 직접 설치가 필요하면 주최 측의 공식 모델 안내에 따라 GPU 서버에서 다운로드합니다. 노트북은 앱 화면과 서버 호출에 사용합니다.

## 3. 실제 Zoro 연결·호환성 점검

기존 `.env`에 `ZORO_BASE_URL`, `ZORO_MODEL`, 필요한 경우 `ZORO_API_KEY`, 대기 제한을 넣고 서버를 다시 시작합니다. `app/zoro_provider.py`는 OpenAI Chat Completions 호환을 가정했으므로, 제공 인터페이스가 다르면 어댑터만 수정합니다. 도구·상태·승인 체계는 재사용합니다.

첫 연결에서는 짧은 요청 하나로 실제 응답과 행동 형식을 확인합니다. 이어 조건 변경 제안 → 사용자 승인 → 도구 실행 → 결과 재관찰을 검증합니다. JSON 출력, 도구 호출, 토큰 제한, 시간 초과, 오류 응답을 각각 확인합니다. 실제 모델 실패는 개발 모드로 자동 대체하지 않습니다.

## 4. 실제 모델 평가와 최종 발표

현재 평가기 `scripts/evaluate_agent.py`는 오프라인 개발 모드 전용입니다. 실제 Zoro 평가 경로를 별도로 만들고 같은 20개 시나리오의 행동 적합성, 잘못된 인수, 승인 절차, 실행 지연을 기록합니다. 기존 오프라인 20/20을 모델 점수로 발표하지 않습니다.

발표는 고객의 조건과 근거 → 현장 확인으로 추천 수정 → 일정 지연에 대한 복구로 구성합니다. 실제 예약·계약·결제·외부 발송은 구현 범위가 아닙니다. 사전 작업 허용 범위와 현장 모델 사용 규정은 주최 측 안내로 최종 확인합니다.
