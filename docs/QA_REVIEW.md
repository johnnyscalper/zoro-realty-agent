# 독립 검증 기록

현재 문서는 준비 단계 1–4의 코드 검증 범위를 설명합니다. 국토부 실제 인증키 및 GPU가 제공되지 않았으므로 실서비스 접속이나 Zoro 추론 성공을 의미하지 않습니다.

## 독립 HTTP·설정 검사

- 키 설정 여부와 실제 연결 검증 상태를 구분합니다. 키나 Zoro 주소를 넣어도 `verified`가 자동으로 참이 되지 않아야 합니다.
- 샘플 모드는 외부 API를 호출하지 않아야 하며 결과에 합성 데이터임을 표시해야 합니다.
- 실제 조회 모드에서 키 누락, 인증 오류, 예외가 발생해도 합성 결과로 바꿔 성공처럼 표시하지 않아야 합니다.
- 매매·전월세 조회에 각각 올바른 서버 측 키를 전달하고 키가 브라우저 응답·상태·로그에 노출되지 않아야 합니다.
- 월·법정동 코드 길이·페이지·금액·면적 입력을 검증합니다. `NaN`이나 무한대도 허용하지 않습니다.
- 매물 필터가 조건을 정확하게 적용하고, 결과가 없으면 조건에 맞지 않는 후보를 대신 넣지 않아야 합니다.
- 정적 파일 경로를 통해 `.env` 및 서버 소스가 열리지 않아야 합니다.
- 가상 매물·현장 확인·일정·시나리오가 서로 다른 검증 단계라는 것을 유지합니다.

## 결과 기록

2026-11-12, 독립 HTTP·설정 검증을 아래 명령으로 실행했습니다.

```bash
python -m pytest tests/test_config.py tests/test_app.py -q --tb=short
```

결과: **52개 통과**. 실제 서비스 호출 없이 `TestClient`와 주입한 가상 조회 함수로 실행했습니다. 개발 도구의 후속 버전 변경에 관한 경고 2개가 있었으며 테스트 실패는 없습니다. 이 수치는 전체 프로젝트 테스트 수가 아닌 독립 HTTP·설정 검사 묶음의 수입니다.

첫 통합 검사에서 가상 자료의 최상위 `notice` 필드를 엄격한 서버 스키마가 거절하여 매물·상태 조회가 실패하는 문제를 발견했습니다. 서버 스키마가 해당 안내 필드를 명시적으로 허용하도록 수정한 뒤 동일 검사를 재실행하여 해결을 확인했습니다.

시나리오 20개는 향후 평가 명세이며 모델 평가 20회 통과라는 뜻이 아닙니다. HTTP 검증을 위해 주입한 가상 성공 응답 역시 실제 국토부 인증키 연결 성공 기록이 아닙니다.

## 아직 검증하지 않은 범위

- 실제 사용자 인증키로 국토부 매매·전월세 API 조회
- 실제 운영 응답 전체 형식, 호출 제한 및 네트워크 환경
- Zoro 서버 설치·접속·판단 품질·지연시간
- 실제 고객 정보, 실제 업체 일정 및 외부 메시지 발송·예약
