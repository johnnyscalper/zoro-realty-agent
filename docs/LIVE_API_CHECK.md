# 사용자 키 연결 및 실조회 점검 — v0.3

점검일: 2026-11-12, 한국 시간. **키 설정은 완료했지만 실제 인증·거래 조회 성공은 미검증이다.**

## 수행 결과

이전 개발 환경에서 서버 전용 설정으로 두 API의 연결을 검사했다. 인증키·설정 파일·원본 응답은 이 공개 저장소에 포함하지 않는다. 아래 기록은 개발 환경의 검사 결과이며 Windows PC의 실행 결과와 구분한다.

최종 명령행 검사 종료: **2026-11-12 20:50:07 KST**. 검사 조건은 강남구 `11680`, 계약월 `202610`, 매매·전월세 각각 첫 페이지 최대 5건이다. 보고서 스키마는 1.1이다.

| 서비스 | 결과 | 코드 | 실제 거래 응답 |
| --- | --- | --- | --- |
| 매매 | FAILED | MOLIT_CONNECTION_ERROR | 받지 못함 |
| 전월세 | FAILED | MOLIT_CONNECTION_ERROR | 받지 못함 |

`both_apis_verified=false`이며 거래 건수는 알 수 없어 null이다. 실패를 거래 0건이나 조회 성공으로 바꾸지 않았다.

## 연결 단계 진단

현재 앱의 기본 직접 접속에서 DNS 관련 `ConnectError`와 이름 해석 실패를 확인했다. 별도로 환경에서 제공하는 프록시·CA를 사용하는 **비인증 진단**은 HTTP 503 및 상위 연결 시간 초과 응답을 받았다. 이 진단에는 사용자 키를 보내지 않았다. 두 결과를 인증된 국토부 응답으로 합쳐 해석하지 않는다.

인증키의 유효성이나 두 서비스의 활용승인 여부를 확인할 응답을 받지 못했다. 이 증거만으로 키 오류 또는 국토부 자체 장애를 확정할 수 없다. TLS 검증을 끄거나 네트워크 제한을 우회하지 않았고, 앱의 기본 직접 접속 정책도 바꾸지 않았다.

## 브라우저에서 확인한 동작

- 매매·전월세가 모두 ‘키 설정됨’으로 표시되며 ‘실제 조회 별도 검증’ 문구가 유지됨.
- 전월세·매매의 실제 조회를 각각 누르면 연결 오류와 조회 미완료를 표시함.
- 실제 조회 실패를 가상 거래로 대체하지 않음.
- 가상 응답 3건을 조회한 뒤 지역 코드를 입력 중에 바꾸면 이전 결과가 즉시 사라짐.
- API 오류 후 기존 상담 ID를 불러와 버전 10과 저장된 청소·이사 일정을 그대로 복원함.

이 화면 검증은 실제 국토부 성공 응답의 값·항목·페이지가 올바르다는 검증이 아니다.

## 다음 검증

다운로드하는 ZIP에는 키가 없다. 현재 작업 환경에 저장한 설정과 사용자 PC의 설정은 별개다. 새 PC 또는 새 압축 해제 폴더에서는 `CONFIGURE_API_KEYS_WINDOWS.cmd`의 별도 창으로 키를 한 번 입력한다. 두 서비스의 키가 같으면 같은 인증키 사용 체크를 유지하고 ‘저장하고 연결 검사’를 누른다. 기존 폴더를 업데이트할 때는 키를 다시 입력하지 않는다.

이미 해당 폴더에 키를 저장했다면 다음 명령으로 연결만 다시 검사할 수 있다.

```text
.venv\Scripts\python.exe scripts\check_api.py --kind both --lawd-cd 11680 --month 202610
```

검사 후 `reports/api_verification_report.json`의 시각·조건·서비스별 상태를 확인한다. 이 파일은 키·단지명·원본 응답을 담지 않으므로 결과 공유용으로 사용할 수 있다. 두 서비스의 OK를 확인한 뒤 실제 거래가 있는 페이지에서 금액·면적·계약일·매매 해제값과 정규화 결과를 대조한다. 정상 0건은 개별 항목 변환을 검증하지 못한다.

이전 점검 당시의 미검증 항목이다. 이후 사용자 Windows PC의 정상 표시 보고는 문서 맨 위에 추가했다. 이 작업 환경의 실제 인증 응답 및 실제 Zoro 추론은 여전히 검증하지 않았다.
