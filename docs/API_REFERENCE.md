# 국토부 API 연결 근거와 검증 범위

확인일: 2026-11-12. 이 문서는 사용자 계정의 인증키를 사용하지 않은 공개 문서 검토 결과와 프로그램의 변환 계약을 구분한다. 실제 국토부 응답을 받았다는 뜻이 아니다.

## 공식 자료에서 확인한 호출 방식

| 구분 | 공식 데이터 | GET 호출 주소 |
|---|---|---|
| 매매 | [국토교통부_아파트 매매 실거래가 자료 · 15126469](https://www.data.go.kr/data/15126469/openapi.do) | `https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade` |
| 전월세 | [국토교통부_아파트 전월세 실거래가 자료 · 15126474](https://www.data.go.kr/data/15126474/openapi.do) | `https://apis.data.go.kr/1613000/RTMSDataSvcAptRent/getRTMSDataSvcAptRent` |

두 서비스는 REST/XML 방식이다. `LAWD_CD`는 법정동 코드 앞 5자리, `DEAL_YMD`는 계약연월 6자리, `serviceKey`는 발급받은 인증키다. 구현은 페이지 단위 요청에 `pageNo`, `numOfRows`를 함께 사용한다. 전체 자료를 받기 위해 필요한 페이지를 한꺼번에 자동 호출하지 않는다.

프로젝트 기본 예시는 `11680`, `202610`이다. 화면에서 다른 5자리 지역 코드와 계약월을 지정할 수 있다. 입력 형식 검사는 코드의 실제 존재 여부를 증명하지 않는다.

## 키 입력과 전송

[공공데이터포털 공식 Swagger 실행 안내](https://www.data.go.kr/images/biz/swagger-guide/gw/gateway_swagger_guide.pdf)의 7번째 페이지는 일반 인증키 **Decoding** 입력을 안내한다. 프로젝트 설정에도 Decoding 값을 권장한다. 프로그램이 HTTP 쿼리 인코딩을 수행하므로 사용자가 별도로 URL 인코딩을 더하지 않는다.

`MOLIT_TRADE_API_KEY`와 `MOLIT_RENT_API_KEY`는 서버 설정이다. 두 서비스에 같은 키를 사용한다면 `MOLIT_API_KEY` 공통 설정을 사용할 수 있지만, 각 서비스에 대한 활용 승인은 별도로 유효해야 한다. 프런트엔드와 Zoro에 키를 전달하지 않는다. percent-encoded 키 호환 처리는 한 번만 디코딩하며 `+`를 공백으로 바꾸지 않는다.

## 응답 변환 계약과 아직 확인하지 못한 부분

현재 공개 페이지의 텍스트 응답 명세는 `header`, `body`까지만 노출된다. 참고 HWP 파일 이름은 확인했으나 문서 본문은 확보하지 못했다. 아래는 **클라이언트가 구현한 파싱 계약**이며, 이번 작업에서 최신 item 명세 전체를 공식 원문이나 인증된 실응답으로 대조 완료한 목록은 아니다.

| 예상 XML 항목 | 프로그램 항목 | 변환 계약 |
|---|---|---|
| `aptNm`, `umdNm` | `apartment_name`, `legal_dong` | 문자열; 현재 매물 이름 또는 재고로 간주하지 않음 |
| `dealYear`, `dealMonth`, `dealDay` | `contract_date` | 유효한 달력 날짜인지 검사 후 ISO 날짜로 조합 |
| `excluUseAr`, `floor`, `buildYear` | `area_m2`, `floor`, `build_year` | 숫자 변환; 누락·잘못된 필수 값은 정상값처럼 채우지 않음 |
| `dealAmount` | `price_krw` | 만원 단위 값을 정수 원화로 변환하는 계약 |
| `deposit`, `monthlyRent` | `deposit_krw`, `monthly_rent_krw` | 만원 단위 값을 정수 원화로 변환하는 계약 |
| `cdealType`, `cdealDay` | `cancelled`, `cancelled_date` | 매매 해제 표식을 유지; 해제 거래를 정상 매매처럼 합산하지 않음 |
| `totalCount`, `pageNo`, `numOfRows` | 전체 건수·페이지 정보 | 실제 응답의 페이지 정보와 반환 건수로 다음 페이지 여부 판단 |

단위 변환, 날짜, 취소 표식, 페이지 처리는 합성 XML에 대한 오프라인 테스트로 검증한다. 첫 실호출에서 금액 단위·필드 누락 표현·해제 값과 날짜 형식·응답 페이지 정보를 공식 실행 결과와 다시 대조해야 한다. 합성 XML을 국토부에서 수집한 실제 표본이라고 표시하지 않는다.

## 공식 포털 오류 표와 처리 기준

두 공식 데이터 페이지의 오류 안내를 바탕으로 오류를 분류한다. HTTP 성공 상태여도 XML 내부 오류가 있을 수 있으므로 둘 다 확인한다. 내부 분류 이름과 HTTP 상태는 사용자 프로그램이 정한 것이며 제공기관의 분류를 대체하지 않는다.

| 포털 코드 | 의미 | 프로그램의 대응 원칙 |
|---|---|---|
| `01`, `04`, `05` | 처리·HTTP 연계·시간 초과 | 안전한 오류 안내; 필요하면 사용자가 재시도 |
| `10`, `12` | 요청 값 오류·서비스 없음 | 입력·호출 주소 확인 안내 |
| `20`, `30`, `31` | 키 누락·접근 거부·미등록·기한 만료 | 키·서비스 승인 상태 확인 안내; 자동 반복 호출 금지 |
| `22`, `23` | 일일·초당 호출량 초과 | 쿼터 오류 표시; 즉시 자동 재호출 금지 |
| `29` | 호출 IP 차단 | 접근 제한 오류 표시 |

제공기관의 원문 오류 메시지에는 요청 내용이 포함될 수 있으므로 브라우저 응답과 로그에 그대로 출력하지 않는다. 성공 응답에서 거래 0건인 경우와 인증 실패는 구분한다. 키 없이 `live` 모드를 요청했거나 실호출이 실패한 경우 가상 자료로 몰래 대체하지 않는다.

공식 페이지에는 개발계정 신청 가능 트래픽이 `10,000`으로 표시된다. 실제 승인 계정의 한도·유효 기간은 본인의 활용신청 화면이 기준이다. 이 프로젝트가 계정의 잔여 호출량을 확인하거나 변경하지 않는다.

## 자료를 해석하는 범위

이 API는 신고된 거래 또는 확정일자 기반 전월세 자료를 제공한다. 현재 매물의 재고, 호가, 입주 가능일, 출입구 계단, 업체 예약 가능 시간은 이 자료로 확인하지 않는다. 그러한 값은 `synthetic` 자료 또는 별도의 현장 확인 결과로 구분한다.

[국토교통부 실거래가 공개시스템 FAQ](https://rt.molit.go.kr/pt/bbs/faqList.do?mobileAt=&qnaProcessSttusCode=1)는 계약일과 신고일의 시차, 신고 이후 공개 절차를 설명한다. API의 ‘실시간’ 표기는 미신고 계약까지 즉시 제공한다는 뜻으로 사용하지 않는다. 조회 시각과 계약일을 화면에 별도로 표시한다.

## 키를 넣은 뒤 확인할 항목

1. 매매와 전월세 각각 작은 페이지로 요청하고 승인 상태를 확인한다.
2. 동일 조건의 공식 포털 실행 결과와 단지명·계약일·면적·금액을 비교한다.
3. 전체 건수와 다음 페이지 처리를 확인한다. 0건 조건도 별도로 확인한다.
4. 원본 자료·설정 키를 결과 보고서에 그대로 붙이지 않고, 성공 여부와 비교 결과만 기록한다.
5. 매매 해제 사례와 전월세의 월세 0원/양수 사례가 확보되면 변환 계약을 추가 검증한다.
