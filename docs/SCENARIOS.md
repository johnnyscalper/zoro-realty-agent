# 평가 문제와 검증 방법

문제의 단일 기준 파일은 [`data/scenarios.json`](../data/scenarios.json)이다. 문제를 수정할 때는 이 파일의 상황과 기대 행동부터 수정한다. 이 문서는 평가 절차를 설명하며 결과를 대신하지 않는다.

## 1. 평가 자료의 의미

평가 문제 20개는 가상 상황으로 구성된다. 문제 수가 20개라는 사실은 20개 모델 시험이 통과했다는 뜻이 아니다. 현재 단계에서는 자료의 형식과 코드의 동작을 점검할 수 있고, 실제 Zoro의 판단은 모델 연결 후에 평가한다.

각 문제는 고유 ID, 제목, 분야, 기존 상황(`given`), 발생 사건(`event`), 기대 행동(`expected_actions`), 금지 행동(`must_not`), 필요한 검증 환경(`verification_stage`)을 가진다.

| 문제 ID | 분야 | 확인하려는 내용 |
|---|---|---|
| S01~S07 | `consultation` | 필수 정보 질문, 조건 충돌, 예산·입주일 준수, 필수와 선호 구분 |
| S08~S12 | `reverification` | 계단 없는 이동, 미확인 정보, 추천을 바꾸는 새 근거, 충돌한 확인 자료 |
| S13~S16 | `schedule` | 입주·청소·이사 의존 관계, 시간 변경, 대안 부재, 선택안 적용 |
| S17~S20 | `api` | 빈 결과, 인증·할당량·연결 실패, 실제 키로 두 API 확인 |

## 2. 서로 다른 검증을 구분하기

| 검증 환경 | 할 수 있는 일 | 이 결과만으로 증명할 수 없는 것 |
|---|---|---|
| `offline` | 고정된 입력과 가상 API 응답으로 파서, 오류 처리, 자료 형식 등을 검사 | 실제 인증키 사용 가능 여부, Zoro의 판단 정확도 |
| `live_api_required` | 사용자 키로 실제 국토교통부에 요청하고 응답 확인 | Zoro의 상담·행동 선택 품질 |
| `zoro_required` | 실제 모델의 행동 선택을 받아 실행 결과까지 관찰 | 모든 미래 고객 상황의 정확성 |

파서나 서버 테스트에는 합성된 XML과 테스트용 키를 사용한다. 테스트 이름·화면·결과 기록에서 실제 국토교통부 호출과 혼동되지 않도록 한다.

`verification_stage`는 필요한 환경을 뜻하며 구현 완료 상태가 아니다. 예를 들어 일정 적용·의존 관계 계산 문제는 GPU 없이 시험할 수 있어도 해당 실행 기능을 구현한 뒤에야 평가할 수 있다. 초기 카탈로그의 환경별 구성은 오프라인 8개, 실제 Zoro 필요 11개, 실제 API 필요 1개이며, S20은 두 API를 각각 확인하는 문제다.

## 3. 후속 모델 평가 절차

1. 초기 데이터를 불러오고 해당 문제의 `given`을 적용한다.
2. 다른 문제의 대화나 상태가 섞이지 않게 새 세션으로 시작한다.
3. `event`를 전달한다. 모델은 실제 사용자 질문과 실제 확인 자료만 받는다. 정답 목록을 프롬프트에 넣지 않는다.
4. 선택된 행동, 도구 입력, 실행 결과, 사용자에게 표시한 결과를 기록한다.
5. `expected_actions`의 의미를 만족하는지 검사한다. 표현만 같은 응답을 통과시키지 않는다.
6. `must_not` 위반을 별도로 검사한다. 금지 행동이 발생하면 다른 요구를 충족했어도 실패로 기록한다.
7. 실패 원인을 모델의 행동 선택, 자료 부족, 프로그램 실행 오류로 구분한다.

순서가 중요한 문제는 질문을 받기 전에 조건을 바꾸는 등의 선행 오류도 실패다. 후보를 제외했다고 말한 것과 내부 후보 상태를 실제로 바꾼 것은 따로 확인한다.

## 4. 기록할 결과

| 항목 | 기록 예 |
|---|---|
| 문제 ID | 카탈로그의 고유 ID |
| 실행 종류 | 코드 검사 / 실제 API / 실제 Zoro |
| 데이터·코드 버전 | 실행에 사용한 파일 버전 또는 커밋 |
| 모델 정보 | 실제로 사용한 모델·서빙 설정; 미연결이면 미연결 |
| 결과 | 미실행 / 통과 / 실패 / 환경 부족으로 실행 불가 |
| 실제 행동 | 선택한 기능과 실제 상태 변경 |
| 근거 | 사용한 자료 ID, 변경 사실, 오류 분류 |
| 지연 시간 | 측정된 요청 시작부터 결과 표시까지의 시간 |
| 미해결 사항 | 재현 절차와 후속 조치 |

서버 주소나 인증키 같은 비밀값은 결과 기록에 쓰지 않는다. 모델의 자유로운 내부 추론문을 정답으로 평가하지 않는다. 선택한 행동과 근거 자료, 실제 결과를 평가한다.

## 5. 발표에 사용할 수 있는 수치

- 코드 테스트 수와 모델 평가 문제 수는 별도로 표시한다.
- 실제로 실행한 문제 수를 분모로 사용하고, 미실행·환경 부족 문제는 따로 적는다.
- 기대 행동 충족률 외에 필수 조건 위반 건수와 실행 오류 건수를 함께 기록한다.
- 응답 시간은 실제 모델 연결 후 측정한다. 모델 실행 환경과 시험 조건을 함께 적는다.
- 개발 중 보고 수정한 문제와 새로 만든 점검 문제를 구분한다. 가능하면 마지막 점검용 문제 일부는 구현 수정 전에 답을 보고 맞추는 방식으로 사용하지 않는다.

현재 패키지의 자료 검증 테스트가 통과해도 **Zoro 미검증, 사용자 키를 사용한 실거래 API 미검증** 상태는 그대로 유지한다. 실제 결과는 실행 후 작성하는 검증 보고서를 기준으로 한다.
