# 집의 다음 · 프로젝트 소개

## 제출용 짧은 소개

집의 다음은 부동산 상담을 “답변 한 번”에서 끝내지 않고, 조건 확인 → 후보 검토 → 현장 정보 재확인 → 이사 일정 조정까지 이어가는 에이전트 프로토타입입니다. 강남구 전세 상담을 예로 필수 조건과 미확인 정보를 구분하고, 중요한 변경은 승인 후 반영합니다. 국토부 매매·전월세 실거래 조회 기능과 Zoro 모델 연결 어댑터를 준비했습니다. 현재 추천 매물과 업체 일정은 가상 데이터이며, 기본 시연은 개발용 규칙 모드로 동작합니다. 11월 19일 실제 모델 서버에 연결해 세 시나리오를 확인했습니다. [심사용 데모와 실행 로그](../submission/README.md)

## 왜 만들었나요?

상담에서는 처음 조건에 맞았던 후보도 현장 확인 결과에 따라 달라집니다. 입주 시각 하나가 늦어지면 청소와 이사 일정도 함께 바뀝니다. 이 프로젝트는 이런 변경을 기억하고, 다음에 확인하거나 실행할 일을 이어가는 흐름을 구현합니다.

## 3분 시연

키나 GPU 없이 시작하려면 처음 시작 창에서 **예시 자료 사용**, 상담 화면에서 **개발용 규칙 모드**를 선택합니다.

| 순서 | 조작 | 보여줄 내용 |
| --- | --- | --- |
| 1 | `안녕하세요`를 입력합니다. | 예산·조건을 묻는 기본 상담 |
| 2 | `01 · 조건으로 찾기`를 보내고 변경을 승인합니다. | 필수 충족·미확인·제외를 구분한 가상 후보 |
| 3 | `02 · 확인 결과 반영`을 보내고 승인합니다. | 현장 정보가 바뀌었을 때 후보 재검사 |
| 4 | `03 · 일정 다시 짜기`를 보내고 승인합니다. | 입주 지연에 따른 청소·이사 충돌과 대안 |
| 5 | 대안을 선택하고 보내기·승인을 진행합니다. | 내부 일정 갱신과 실행 내역 |

`04 · 과거 자료 조회`는 별도 데이터 조회 예시입니다. **실거래 데이터 → 국토부 실제 조회**를 선택하고 유효한 API 키가 있을 때만 실제 국토부 조회가 실행됩니다. 이 선택을 켜도 추천 후보 20개는 계속 가상 자료입니다.

## 구현과 검증

- Python/FastAPI 서버, HTML/CSS/JavaScript 화면, SQLite 상담 상태 저장
- 허용된 도구만 실행하고 도구 인수를 검증하며, 중요한 변경은 승인 후 반영
- API 키는 서버 설정에서만 사용하고 공개 파일·프런트엔드·로그에 포함하지 않는 구조
- 11월 16일 1차 공개본의 오프라인 자동 검사 **1,231개 통과**. 이 수에는 개발 모드 HTTP 평가 20개가 포함됩니다.
- 11월 19일 Windows 앱 검사기와 행사 L40S를 연결해 후보 검색, 현장 재검증, 입주 지연을 실행했습니다. 세 사례가 각각 6.44초, 4.103초, 10.42초에 통과했습니다.

자세한 증거와 한계는 [검증 기록](VERIFICATION_V043.md)을 참고하세요. 모델 연결 전의 개발 규칙 검사 결과를 Zoro 성능 점수로 해석하지 않습니다.
