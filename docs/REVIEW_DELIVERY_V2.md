# v0.2 전달·설치·주장 범위 독립 검토

검토일: 2026-11-12. 대상은 Windows 비개발자에게 전달할 로컬 실행 패키지와 기존 1~4단계에서 5단계 실행실로 이어지는 사용 흐름이다. 실제 Windows 장비, 사용자 국토부 인증키, Zoro 모델은 사용하지 않았다. Linux의 별도 Python 환경에서 정적 검토와 오프라인 검사를 수행했다.

## 직접 실행한 결과

```bash
python -m pytest -q tests/test_review_delivery_v2.py tests/test_package.py tests/test_key_setup.py
```

결과: **58개 통과, 실패 0개**. 검토 시점의 묶음 결과이며 전체 프로젝트 검사 수나 모델 평가 수가 아니다. 국토부 연결은 모의 함수로 검사했고 외부 요청을 보내지 않았다.

## 비개발자 전달 시 유지할 흐름

1. ZIP을 완전히 압축 해제하고 Python 3.11 이상을 설치한다. `START_WINDOWS.cmd`로 실행한다. 최초 의존성 설치에는 인터넷이 필요하며 관리자 실행을 전제로 하지 않는다.
2. 키 없이 기존 가상 매물·예시 거래·시연 설계를 보고, 실행실에서 새 상담을 만든다. 필수 조건과 선호를 저장한 뒤 후보·미확인·제외 목록을 확인한다.
3. 확인 작업은 생성만으로 사실을 바꾸지 않는다. 시연용 확인값을 명시적으로 제출하면 해당 사실과 후보 분류가 바뀐다. 계단 수만으로 다른 접근 경로의 부재를 확정하지 않는다.
4. 입주 가능 시각을 바꾸면 기존 청소·이사와의 충돌이 보인다. 대안을 계산한 뒤 사용자가 선택해야 내부 일정표가 바뀐다. 이는 실제 업체 예약이 아니다.
5. 계속 사용할 세션 ID를 별도로 보관한다. 같은 서버의 같은 상태 파일을 유지한 채 다시 실행하고 해당 ID를 불러온다. `.runtime`을 삭제하거나 상태 파일이 없는 새 압축 해제 폴더를 사용하면 이전 상담을 복원할 수 없다. 버전 충돌 안내에서는 최신 상태를 불러와 검토한다.
6. 실제 API 확인을 원할 때 `CONFIGURE_API_KEYS_WINDOWS.cmd`에서 키를 숨김 입력한다. 설정 도구는 앱에 필요한 의존성을 준비한 뒤 실행되며, 키 저장과 실제 조회 확인을 구분한다. 키는 채팅이나 명령행 인수로 받지 않는다.
7. 두 API 실호출에 명시적으로 동의한 뒤 생성되는 `reports/api_verification_report.json`의 실행 시각과 서비스별 상태를 읽는다. 키 저장 성공만으로 연결 성공을 선언하지 않는다. 0건 정상 응답은 개별 거래 필드 변환까지 입증하지 않는다.

## 범위와 남은 확인

- 사용자 인증키가 제공되지 않아 실제 매매·전월세 API 인증·응답 호환성을 확인하지 않았다. 기존 모의 API 검사나 키 설정 검사를 실호출 성공으로 바꾸어 보고하지 않는다.
- 모델 다운로드·서빙·추론·자연어에서 도구 선택·모델 응답 속도를 확인하지 않았다. 5단계 결과는 결정적인 코드 도구를 사람이 조작한 결과다.
- Windows 실행기의 경로 처리와 호출 순서는 코드로 검토했고 ACL 호출은 모의 검사했다. 실제 Windows 설치·실행·키 숨김 입력·권한 적용은 아직 실기기 검증이 필요하다.
- 브라우저 조작은 이 독립 전달 검토에서 수행하지 않았다. UI 수정 후 실제 브라우저의 조건 해제·새로고침·세션 복원·버전 충돌 검증은 최종 통합 기록을 따른다.
- 포장 규칙은 비공개 경로·파일과 심볼릭 링크 혼입을 막는다. 허용된 소스나 공개 문서에 사람이 직접 적은 비밀까지 탐지하는 비밀 검사 도구는 아니다.
- 외부 배포·메시지 발송·실제 예약·실제 고객 데이터를 사용하지 않았다.

검토자가 수정한 파일은 이 기록과 `tests/test_review_delivery_v2.py`뿐이다. 기능 구현·시작 문서·최종 배포 파일은 담당자가 통합하며, 전체 검사 결과와 최종 브라우저 결과는 `VERIFICATION.md`를 기준으로 한다.
