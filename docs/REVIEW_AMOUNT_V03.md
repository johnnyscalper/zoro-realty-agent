# v0.3 원화 금액 정밀도 경계 검토

검토일: 2026-11-12. 범위: `app/molit.py`의 금액 상한과 `_money`,
새 회귀 검사 `tests/test_amount_v03.py`. 합성 XML만 사용했으며 네트워크
요청, 실제 키·설정 파일 및 사용자 업로드 열람은 하지 않았다.

## 발견한 문제와 수정

기존 `_money`는 만원 문자열을 `Decimal`로 변환한 뒤 최대 `10**17`원까지
정수로 반환했다. Python 정수와 JSON 숫자 표기는 정확해도 브라우저의
JavaScript `Number`는 이 범위의 모든 정수를 정확히 표현하지 못한다.
예를 들어 `900719925474.0993`만원은 `9,007,199,254,740,993`원이지만,
브라우저에서 JSON 숫자로 읽으면 `9,007,199,254,740,992`원으로 바뀐다.

정규화된 원화의 상한을 `MAX_MONEY_KRW = 9_007_199_254_740_991`
(`2**53 - 1`, `Number.MAX_SAFE_INTEGER`)로 제한했다. 정확한 만원 상한은
`900719925474.0991`이다. 경계 바로 위의 `2**53` 자체는 표현 가능하지만,
모든 반환 금액에 동일한 안전 정수 규칙을 적용하기 위해 제외한다.

`Decimal`을 통한 만원→원 변환, 쉼표 구분, 소수점 이하 최대 네 자리의
1원 단위 보존, 정수 JSON 필드 형식은 그대로다. 반올림하거나 숫자를 문자열로
바꾸지 않는다. 변경한 운영 코드 범위는 상수 추가와 `_money`의 상한 비교뿐이다.

## 영향을 받는 필드와 행 처리

| 제공기관 필드 | 반환 필드 | 상한 이내 | 상한 초과 |
|---|---|---|---|
| `dealAmount` | `price_krw` | 1원부터 상한까지 정확히 보존한다. 기존 매매 0원 제외 규칙을 유지한다. | 해당 매매 행 전체를 제외한다. |
| `deposit` | `deposit_krw` | 0원부터 상한까지 정확히 보존한다. | 해당 전월세 행 전체를 제외한다. |
| `monthlyRent` | `monthly_rent_krw` | 0원부터 상한까지 정확히 보존한다. 월세 0원은 기존처럼 전세로 분류한다. | 해당 전월세 행 전체를 제외한다. |

기존 유효하지 않은 행 처리 경로를 사용한다. 제외한 행은 `skipped_count`에
포함하고 제외 건수 경고를 남기며, 제공기관의 `total_count`는 유지한다.
같은 응답의 정상 행과 해당 행의 원래 인덱스는 유지된다. 모든 행이 제외되어도
`total_count`와 `skipped_count`를 보존하므로 제공기관이 0건을 반환한 것처럼
보이지 않는다. 일반적인 금액 범위의 동작은 바뀌지 않는다.

## 검증 결과

새 검사 파일은 30개 사례로 다음을 확인한다.

- 세 금액 필드 각각에서 1원, 일반적인 소수 만원, 상한 바로 아래와 상한 값을
  정확히 변환한다. 상한은 쉼표가 있는 표현도 확인한다.
- 반환 정수가 JSON을 거쳐 IEEE-754 binary64로 읽혀도 동일한 원화 값이다.
  이 검사는 Python의 `json.loads(..., parse_int=float)`를 사용하며 실제
  브라우저 실행 검사는 아니다.
- 상한보다 1원·2원 큰 값과 기존 `10**17`원 상한을 제외한다. 정상 행 보존,
  제공기관 전체 건수, 제외 건수, 경고와 원래 행 인덱스를 함께 검사한다.
- 모든 행이 상한을 초과한 응답의 제외 건수를 유지한다.
- 매매 0원 제외, 보증금·월세 0원 허용, 전세 분류를 유지한다.
