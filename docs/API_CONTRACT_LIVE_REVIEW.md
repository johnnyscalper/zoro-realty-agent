# MOLIT 공개 API 계약 재검토

확인일: 2026-11-12. 검토 대상은 `docs/API_REFERENCE.md`와 `app/molit.py`이며, 아래는 **공식 공개 자료와 구현의 대조 결과**다. 이 문서의 `LIVE`라는 파일명은 인증된 실호출 성공을 뜻하지 않는다. 인증키·`.env`·업로드 파일을 열지 않았으며, 인증된 API 호출도 수행하지 않았다.

## 공식 자료에서 재확인한 범위

| 대상 | 공식 근거 | 확인 결과 |
|---|---|---|
| 매매 서비스 | [15126469 공식 페이지](https://www.data.go.kr/data/15126469/openapi.do) | 공개된 base URL과 `GET /getRTMSDataSvcAptTrade`는 구현의 `ENDPOINTS["trade"]`와 일치한다. 데이터 형식은 REST/XML이다. |
| 전월세 서비스 | [15126474 공식 페이지](https://www.data.go.kr/data/15126474/openapi.do) | 공개된 base URL과 `GET /getRTMSDataSvcAptRent`는 구현의 `ENDPOINTS["rent"]`와 일치한다. 데이터 형식은 REST/XML이다. |
| 공통 필수 요청 | 위 두 공식 페이지의 요청변수 표 | `LAWD_CD`는 법정동 코드 앞 5자리, `DEAL_YMD`는 계약연월 6자리, `serviceKey`는 포털 인증키다. 코드의 대소문자와 조회 의미가 일치한다. |
| 키 입력과 전송 | [공식 Swagger 실행 안내 PDF](https://www.data.go.kr/images/biz/swagger-guide/gw/gateway_swagger_guide.pdf), 7쪽 | Swagger 입력에는 Decoding 키를 사용한다. 각 서비스의 요청 표가 URL Encode 키를 예시로 드는 것과 충돌하지 않는다. 입력값과 HTTP 쿼리의 인코딩 단계가 다르다. |
| 응답 명세의 공개 범위 | 위 두 공식 페이지의 출력결과 표 | 이번 검색·열람에서는 `header`, `body`만 확인됐다. item 필드별 자료형·필수 여부·단위·열거형까지 공개 원문으로 확인하지 못했다. |

확인된 전체 호출 주소:

```text
https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade
https://apis.data.go.kr/1613000/RTMSDataSvcAptRent/getRTMSDataSvcAptRent
```

공식 페이지는 매매 동정보의 공개 조건을 소유권 이전등기 완료와 연결하며, 전월세 동·호정보는 제공하지 않는다고 설명한다. 이는 `umdNm` 같은 법정동 명칭과 아파트 건물 동·호를 구분해야 한다는 의미다. 현재 응답의 `legal_dong`을 세대의 건물 동·호로 표시하면 안 된다. 위 두 페이지가 표시한 수정일은 각각 2026-07-22와 2026-07-29다.

## 구현과 공개 근거 사이의 구체적인 차이

다음 표의 “미확인”은 지원하지 않는다는 판정이 아니다. 이번에 확보한 **공식 원문만으로는 계약을 확정할 수 없다는 뜻**이다. 구현에서 의도적으로 둔 범위 제한 역시 제공기관의 한도로 설명하면 안 된다.

| 항목 | 현재 구현 | 공식 근거와 대조한 판단 |
|---|---|---|
| 키 정규화 | `_normalize_key()`가 percent encoding을 한 번 해제하고, `httpx`의 `params`가 전송 쿼리를 인코딩한다. `+`를 공백으로 바꾸지 않는다. | Decoding 입력 권고와 일치한다. 키를 URL 문자열에 직접 붙이거나 이중 인코딩하도록 바꿀 근거가 없다. |
| 페이지 요청 | `pageNo`, `numOfRows`를 전송한다. 앱 자체가 페이지 번호 1–10,000과 건수 1–100을 허용한다. | 확보한 공식 요청표에는 세 필수 요청값만 표시됐다. 페이지 인자의 존재·기본값·최대값은 공개 원문으로 재확인하지 못했다. **100은 앱 제한이며 공식 최대값으로 확인된 값이 아니다.** |
| 공통 item 필드 | `aptNm`, `umdNm`, `dealYear`, `dealMonth`, `dealDay`, `excluUseAr`, `floor`를 필수 처리한다. `buildYear`, `sggCd`는 선택적으로 읽는다. | 정확한 XML 이름과 누락 가능 여부는 공식 item 명세 또는 실제 응답 대조가 남았다. 특히 선택적인 `buildYear`와 필수 `floor`의 차이는 제공기관의 필수 구분이 아니라 현재 파서 계약이다. |
| 금액 | 매매 `dealAmount`, 전월세 `deposit`, `monthlyRent`에 10,000을 곱한다. 전월세 월세가 0이면 `jeonse`로 분류한다. | 이번 공식 열람 결과에는 금액 필드·단위가 나오지 않았다. 변환은 구현 가정으로 유지하고, 성공 응답의 단위와 의미를 별도로 확인해야 한다. |
| 매매 해제 | `cdealType`의 빈 값, `-`, `O`, `Y`, `N`, `0`, `1`을 허용한다. `cdealDay`가 있으면 해제로 처리한다. | 전체 허용 표식과 날짜 형식은 공식 원문으로 확인하지 못했다. 구현의 호환 범위를 공식 열거형으로 소개하면 안 된다. |
| 해제 날짜 | `YYYYMMDD`, `YYYY-MM-DD`, `YYYY.MM.DD`, `YY.MM.DD`를 처리한다. 두 자리 연도는 2000년대로 해석한다. | 포맷과 세기 해석은 구현 규칙이다. 실제 표본 또는 기술문서로 확인해야 한다. |
| 전월세 해제 | `cancelled=false`와 `cancellation_status_available=false`를 반환한다. | 첫 값만으로 계약의 현재 유효성을 증명하지 않는다. 현재 경고 문구와 availability 값을 함께 보존해야 한다. 공개 텍스트로 전월세 해제 필드 유무를 확정하지 않았다. |
| 행 제외 | 면적·층·건축연도 등의 자체 범위를 검사하고 위반 행을 `skipped_count`로 센다. 건축연도는 계약연도 이하만 허용한다. | 이 범위는 앱의 방어적 검증이다. 제공기관이 보장하는 전 범위와 같다고 확인하지 않았다. 성공 응답에서도 제외 건수가 생길 수 있다. |
| 페이지 응답 | `totalCount`, `pageNo`, `numOfRows`를 필수로 읽고, 응답 페이지·건수가 요청값과 정확히 같아야 한다. `page_no * num_of_rows < total_count`로 다음 페이지를 판정한다. | 필드별 응답 계약과 서버의 건수 보정 여부를 공식 원문으로 확인하지 못했다. 첫 페이지가 성공했다는 사실만으로 마지막 페이지와 0건 처리를 검증한 것은 아니다. |
| 무자료 응답 | 코드 `03` 또는 `NODATA_ERROR`/`NO_DATA`를 빈 목록으로 처리한다. | 이번 공식 오류표에서 이 무자료 계약을 확인하지 못했다. 코드 `03`에 대한 호환 처리는 실제 표본 없이 공식 보장이라고 표시하지 않는다. |

## 인증·오류 계약

[매매](https://www.data.go.kr/data/15126469/openapi.do)와 [전월세](https://www.data.go.kr/data/15126474/openapi.do) 공식 오류 안내에서 인증·권한 관련 `20`, `30`, `31`, 호출량 제한 `22`, `23`, IP 차단 `29`를 확인했다. 따라서 “키가 존재함”과 “해당 서비스의 활용 권한이 유효함”은 구분해야 한다. 같은 키를 두 엔드포인트에 쓰더라도 두 서비스의 호출 성공을 각각 확인해야 한다.

`_service_error()`는 위 코드를 별도 실패로 분류한다. 추가로 처리하는 `21`, `32`, `33`, `11`과 여러 문자열 토큰은 현재 구현의 호환 범위이며, 이번에 재확인한 두 페이지의 오류표에 모두 열거된 계약은 아니다. 실패 시 가상 자료로 대체하지 않고 고정된 공개 오류 메시지를 사용한다는 현재 구현 원칙은 유지할 수 있다.

공식 페이지의 개발계정 표시는 10,000이다. 이를 현재 계정의 남은 호출 수나 모든 승인 계정의 확정 한도로 해석하지 않는다.

## 검색·열람 한계

- 두 공식 페이지의 검색 결과에서 GET operation 이름과 참고 HWP 파일 이름은 확인했다. 그러나 HWP 본문이나 전체 item 스키마를 검색·열람 가능한 공식 원문으로 확보하지 못했다.
- [매매 catalog JSON](https://www.data.go.kr/catalog/15126469/openapi.json)과 [전월세 catalog JSON](https://www.data.go.kr/catalog/15126474/openapi.json)은 JSON-LD 데이터셋 메타데이터다. 이름에 `openapi.json`이 포함되더라도 응답 필드가 정의된 전체 OpenAPI/Swagger 스키마로 사용하면 안 된다.
- 제공기관·포털 도메인에서 필드명과 기술문서명을 추가로 검색했으나 이번 검색에서는 item 계약을 확정할 공식 문서를 얻지 못했다. 비공식 예제·블로그·다른 데이터셋의 필드를 대신 근거로 사용하지 않았다.
- 웹 검색 결과는 승인 계정 상태·실제 네트워크 도달성·실시간 성공 응답을 증명하지 않는다. 이 검토는 `.env`, 업로드, 인증키 이미지, 인증 응답을 읽지 않았다.

## 실제 호출 담당자가 기록할 최소 결과

1. 매매·전월세 각각에 대해 요청한 지역·계약월·페이지, HTTP 성공 여부, 제공기관 성공 코드, 전체/반환/제외 건수를 기록한다. 키와 전체 요청 URL은 기록하지 않는다.
2. item의 필드 존재·금액 단위·날짜 형식·해제 표식·전월세 0원/양수 월세를 공식 실행 결과와 대조한다. 확보하지 못한 사례는 미검증으로 남긴다.
3. 페이지 정보가 요청과 일치하는지 확인한다. 추가 호출은 작은 페이지로 제한하며, 마지막 페이지 또는 0건을 실제로 확인하지 않았다면 별도 미검증으로 남긴다.
4. 성공 표본이 있더라도 이를 전체 item 명세 검증 완료나 모든 지역·월의 데이터 품질 보장으로 확대하지 않는다.

결론: 공개 자료와 비교해 호출 주소·필수 조회 의미·키 입력 방식의 변경이 필요하다는 근거는 발견되지 않았다. 현재 문서의 item 명세 미확인 설명은 정확하며, 인증된 표본을 확보하기 전 이를 “전체 실거래 API 계약 검증 완료”로 바꾸면 안 된다.
