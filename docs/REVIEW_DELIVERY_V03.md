# v0.3 전달물·로컬 설정 보존 검토

검토일: 2026-11-12. 이 검토는 공개 코드와 합성 설정만 사용했다. 실제 `.env`, 인증키, 사용자 첨부 이미지는 열거나 복사하지 않았다. 배포 ZIP 생성과 최종 ZIP 검사는 통합 담당자가 수행한다.

## 전달물과 인증키의 구분

통합 담당자가 사용자 제공 인증키를 현재 작업 환경의 비공개 `.env`에 저장했다고 전달했다. 이 사실은 인증키가 다운로드 파일에 포함되거나 사용자 PC에 설치되었다는 뜻이 아니다.

| 대상 | 확인한 범위 | 전달 시 설명할 내용 |
| --- | --- | --- |
| 공개 코드 패키지 | `scripts/build_package.py`의 경로·확장자 허용 목록 검토 | 앱·실행기·빈 설정 예제·설명서를 전달한다. 실제 인증키는 포함하지 않는다. |
| 현재 작업 환경의 인증키 | 저장 사실은 통합 담당자의 기록이며 이 검토에서 값을 읽지 않음 | 현재 작업 환경의 설정이다. 다운로드하거나 새 PC에서 압축을 풀 때 자동으로 옮겨지지 않는다. |
| 사용자 PC의 새 압축 해제 폴더 | 처음 실행 시 빈 `.env`를 만드는 코드 확인 | 실제 조회를 하려면 그 PC에서 `CONFIGURE_API_KEYS_WINDOWS.cmd`로 로컬 키를 설정해야 한다. |
| 사용자 PC의 기존 사용 폴더 | 시작 시 기존 `.env`를 덮어쓰지 않는 회귀 검사 통과 | 기존 폴더에서 공개 코드를 교체하고 실행하면 설정은 유지된다. 새 폴더에는 기존 상담 DB와 설정이 없다. |
| 실제 국토부 응답 | 이 검토에서는 네트워크 호출하지 않음 | 최종 호출 시각·서비스별 결과는 `VERIFICATION.md`와 비밀값 없는 실호출 보고서를 따른다. |

검토 착수 시 통합 담당자는 공급자 응답 이전의 연결 오류(`ConnectError`)를 조사 중이었다. 연결 오류만으로 키의 유효성·활용승인·응답 항목 변환을 판단하면 안 된다. 이후 실제 응답이 있으면 그 결과를 최종 통합 기록에 반영해야 한다. 키 저장, 모의 응답 검사, 실제 인증 응답은 각각 별개 근거다.

## 코드와 실행기 검토

- 포장 허용 목록은 실제 `.env`, 변형된 숨김 설정 파일, `.venv`, `.runtime`, `reports`, 캐시, 심볼릭 링크 파일을 선택하지 않는다. `.env.example`은 공개 설정 예제로 포함된다.
- `START_WINDOWS.cmd`는 자기 폴더로 이동한 뒤 `scripts/bootstrap.py`를 호출한다. 실행기에는 인증키를 담거나 환경 파일을 덮어쓰는 명령이 없다.
- `bootstrap.py`는 `.env`가 없을 때만 예제를 복사한다. 의존성이 바뀌어 재설치하는 정상 시작 경로에서도 기존 설정의 내용을 읽거나 덮어쓰지 않는다. 설치 실패 때에는 앱을 시작하지 않고 기존 설정과 이전 설치 표시를 보존한다.
- 키 설정 도구는 별도 실행이다. 기존 키를 자동으로 다시 묻는 시작 흐름이 아니며, 키를 명시적으로 바꿀 때 다른 설정을 보존한다. 실행 중인 앱은 키 변경 후 재시작해야 한다.
- 로컬 상담 상태는 `.runtime`에 남는다. 배포 패키지나 상담 ID만으로 다른 PC 또는 새 폴더에 옮겨지지 않는다.

허용 목록은 파일 선택 규칙이다. 공개 소스나 문서에 사람이 직접 넣은 비밀값까지 자동 탐지하는 검사는 아니므로 최종 배포 전 비밀값 검토는 별도로 필요하다. 이 검토에서는 실제 키 값을 조회하거나 비교하지 않았다.

## 추가한 회귀 검사

기존 검사는 설치가 이미 끝난 `--no-run` 경로의 설정 보존을 확인했다. 실제 업데이트 뒤 일반 시작 경로에서 의존성 재설치가 필요할 때의 설정 보존은 별도 검사가 없어 `tests/test_delivery_v03.py`에 추가했다.

| 검사 | 결과 |
| --- | --- |
| 의존성 변경 → 설치 성공 → 앱 시작 | 합성 키·사용자 포트·DB 경로·CRLF를 포함한 기존 `.env`가 바이트 단위로 유지됨 |
| 의존성 변경 → 설치 실패 | 기존 `.env`와 이전 설치 표시 유지, 앱 시작 안 함 |
| 두 경로의 콘솔 출력 | 합성 키가 출력되지 않음 |

실행: `../zoro-clean-check/bin/python -m pytest -q tests/test_delivery_v03.py` → **2 passed**. 임시 폴더와 대체된 하위 프로세스만 사용했다. 패키지 설치, 서버 실행, ZIP 생성, 실제 API 호출은 수행하지 않았다.

## 검토 한계와 최종 전달 문구

Windows 실행기의 호출 경로를 코드로 검토했으며 Windows 실기기에서 설치·더블클릭·숨김 입력을 실행한 결과는 아니다. 이 검토의 테스트 통과를 Windows 실기기 검증으로 표현하면 안 된다. 전체 자동 검사, 실제 브라우저 결과, 최종 패키지 검사 및 실호출 판정은 통합 검증 기록이 기준이다.

최종 안내에는 최소한 다음 의미가 모두 드러나야 한다: **코드는 다운로드 가능하며, 제공받은 키는 현재 작업 환경에만 설정되어 있고, ZIP에는 키가 없으므로 새 PC에서 실제 조회하려면 그 PC에도 키를 설정해야 한다.** 실제 API 성공 여부는 최종 실호출 결과에 맞춰 따로 설명한다. Zoro 추론·도구 선택이나 실제 업체 예약을 검증한 전달물로 설명하지 않는다.

이 검토에서 작성한 파일은 이 문서와 `tests/test_delivery_v03.py`뿐이다.
