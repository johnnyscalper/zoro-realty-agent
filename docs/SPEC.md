# 집의 다음 — 기능 명세 v0.4

기준일: 2026-11-12 · 대상: 강남구 아파트 전세 상담 · 범위: 사전 준비 1~4단계 + ⑤ 실행 도구 + ⑥ 상담 에이전트

## 목적과 구현 범위

고객 조건으로 후보를 분류하고, 새로운 현장 확인 결과로 후보를 재검사하며, 입주 지연에 맞는 청소·이사 대안을 계산한다. 상담 화면의 개발용 규칙 플래너가 다음 도구를 선택하며, 변경은 사용자가 검토한 뒤 승인한다. 기존 실행실의 수동 도구도 유지한다. 별도 Zoro 어댑터는 구현했지만 실제 서버 규격과 모델 성능은 미검증이다.

| 기능 | 입력 | 선택·실행하는 행동 | 완료 기준 |
| --- | --- | --- | --- |
| 기본 상담 | 예산·면적·입주 기한·필수 접근성·선호 | 조건 저장, 후보 검색, 과거 거래 참고 조회 | 충족·확인 필요·제외를 이유와 함께 표시하고 예산 미입력은 미완료로 유지 |
| 추천 재검증 | 매물별 확인 항목, 사람이 입력한 관찰, 계약 상태 | 확인 작업 생성, 결과 기록, 후보 재계산 | 새 확인 사실만 반영하며 후보 분류와 변경 이력이 함께 바뀜 |
| 일정 복구 | 입주 가능 시각, 소요 시간, 선행 관계, 제공된 가상 슬롯 | 충돌 확인, 대안 생성, 선택안 적용 | 충돌 없는 저장 대안만 사용자가 선택해 내부 일정에 반영 |
| 상태 관리 | 상담 ID·현재 버전 | 별도 상담 생성·저장·복원 | 서버 재시작 후 복원, 상담 간 격리, 오래된 변경은 409로 거부 |
| 국토부 조회 | 거래 종류·지역 코드·계약월·페이지 | 매매·전월세 요청과 정규화 | 안전한 오류 분류, 샘플과 실제 분리. 실제 성공은 사용자 키로 별도 검증 |

## 필수 조건·선호·미확인

필수 조건은 최대 보증금, 최소 전용면적, 입주 기한, 무단차 접근성, 엘리베이터다. 미지정은 `null`이며 `false`와 다르다. 선호는 소음 수준과 희망 동으로 순위에만 반영한다. 금액은 정수 원화, 면적은 ㎡, 일정은 시간대가 포함된 ISO 시각이다.

- 필수 조건을 자동으로 완화하지 않는다. 예산이 없으면 추가 입력이 필요하며 조건 충족 후보를 확정하지 않는다.
- 필수 정보가 미확인이면 확인 필요, 확인된 위반이나 계약 완료면 제외한다.
- 선호 소음이 다르다는 이유만으로 제외하지 않는다. 소음 미확인을 조용함으로 취급하지 않는다.
- 엘리베이터 있음은 전체 동선의 무계단 접근성을 증명하지 않는다.
- 계단 수만으로 대체 출입구·경사로의 부재를 추정하지 않는다. 해당 항목을 별도로 확인한다.
- 확인 작업 생성은 관찰이 아니다. 사람의 확인값 입력 뒤 해당 필드만 바뀐다.

개발용 규칙은 제한된 한국어 표현에서 지원 조건을 추출하고 검토 카드를 보여준다. 예산 누락, 모호한 값, 부정문, 미지원 필수 조건은 질문으로 처리한다. 일반 언어 모델의 이해 능력을 대신한다고 주장하지 않는다. 실행실의 구조화된 입력도 사용할 수 있다.

## 자료의 의미

| 자료 | 출처와 표시 |
| --- | --- |
| 실제 매매·전월세 | 국토부의 신고된 과거 계약 기록. 현재 매물·입주·소음·접근성을 뜻하지 않음 |
| 예시 거래 | `synthetic_sample`, 합성 자료 |
| 추천 후보 20개 | `data/listings.json`, 가상 매물 |
| 현장 확인 11개와 새 기록 | 가상 현장 자료 및 사용자가 입력한 시연 관찰 |
| 업체 가능 시간 | 가상 시간표. 실제 예약 재고가 아님 |

실제 API 오류를 예시 자료로 대체하지 않는다. 화면의 원본 자료 탭은 초기 시연 자료를 보여주며 실행실의 변경은 해당 상담에만 저장한다. 원본 JSON과 다른 상담에는 영향을 주지 않는다.

## 상태와 변경

SQLite에 상담 조건·가상 매물 사본·확인 작업·관찰 이력·일정·대안·최근 200개 실행 기록을 저장한다. 비밀 키는 상담 DB에 넣지 않는다. 기본 경로는 `.runtime/realty.sqlite3`다.

| 변경 | 처리 |
| --- | --- |
| 조건 교체 | 이전 검색 결과를 지우고 재검색 필요 표시 |
| 확인 결과·계약 상태 변경 | 기존 검색이 있으면 재계산 |
| 계약 완료 | 후보 제외, 해당 매물의 대기 확인 작업 취소 |
| 상담 변경 | 이전 일정 대안 무효화 |
| 일정 대안 적용 | 저장된 ID·현재 버전·시간 제약을 다시 검사하고 대안 목록 비움 |

각 변경은 원자적으로 저장한다. 실패하면 일부만 반영하지 않는다. 모든 변경 요청은 `expected_revision`이 필요하다. 두 창에서 같은 버전을 수정하면 하나만 성공한다. 중복 대기 확인 작업은 재사용하지만, 완료 작업을 조용히 수정할 수 없다. 정정하려면 새 확인 작업을 만들고 새 관찰을 입력한다.

현재는 사람이 제출한 확인 결과를 기록한다. 여러 출처가 서로 다른 주장을 하는 상황을 독립적으로 저장·판정하는 구조는 후속 작업이다.

## 일정 복구의 경계

입주·청소·이사와 등록된 여섯 가상 시간 창을 다룬다. 입주 일정의 종료가 접근 가능 시각이며, 입주 변경은 후속 작업을 자동 이동하지 않는다. 청소 완료 후 이사 등 선행 관계를 지키고 원래 작업 길이를 보존한다. 하나의 제공 시간 창 안에 전체 작업이 들어가야 하며 떨어진 창을 합쳐 가용 시간으로 만들지 않는다.

대안은 슬롯별 가능한 가장 이른 배치에서 최대 다섯 개를 결정적으로 반환한다. 모든 가능한 시각의 열거는 아니다. 다른 날의 대안도 사람이 선택해야 반영한다. 업체별 인원·차량 용량, 이동·준비 시간, 실제 슬롯 만료는 다루지 않는다.

이번 입력은 고정 세 작업이므로 규모가 작다. 더 큰 일정·사용자 임의 슬롯을 받도록 확장하기 전에는 `REVIEW_SCHEDULE_V2.md`의 조합 탐색 비용 제한을 보완해야 한다. 현재 공개 API는 임의 일정 목록을 받지 않는다.

## API·보안 수용 기준

- 지역 코드 5자리, 유효한 계약월, 페이지·건수·거래 종류를 검사한다.
- 매매 금액·보증금·월세의 만원을 정수 원화로 정리하며 전세와 월세, 매매 해제 표시를 구분한다.
- 정상 빈 결과, 인증·할당량·시간 초과·연결·잘못된 XML 오류를 구분한다.
- API 키·요청 URL·원본 오류를 응답이나 공유 로그에 노출하지 않는다.
- 키 설정 여부와 실호출 검증을 구분한다. Windows 키 입력은 마스킹된 별도 창과 원자적 저장을 사용한다.
- 요청 본문의 실제 수신량을 64KiB로 제한하고 같은 출처 JSON 변경만 받는다.
- 제출 ZIP에는 `.env`, 상담 DB, 실행 보고서, 가상환경, 모델 가중치를 포함하지 않는다.

코드 검사는 오프라인 합성 응답으로 수행한다. 실제 인증 응답과 항목별 필드 대조는 사용자 키 입력 후에만 검증 완료로 기록한다. 상세 인터페이스는 `CONTRACT_STAGE5.md`, API 근거는 `API_REFERENCE.md`, 20개 상황 대응은 `STAGE5_SCENARIOS.md`를 따른다.

v0.3에서는 보고서 조건 기록, 오류·무자료·페이지 모순 처리, 정수 금액 범위, HTTP 로그 비밀값 보호, 입력 중 화면 갱신을 보완했다. 사용자 키를 설정해 시도한 실제 연결 결과는 `LIVE_API_CHECK.md`를 따른다.

## 다음 단계

사용자 PC에서 두 API 정상 표시를 확인받았다. 다음은 행사 GPU의 모델 호출 규격 확인 → 구현된 어댑터 호환성 조정 → 실제 Zoro 연결 → 20개 상황의 실제 모델 행동 평가다. 업체 메시지 초안은 후속 구현이며 실제 예약·계약·결제·외부 발송은 현재 범위 밖이다.

## 상담 에이전트 수용 기준

- `development`와 `zoro`, `sample`과 `live`를 독립 선택하고 실제 사용 여부·출처를 표시한다.
- 조건·현장 결과·매물 상태·입주 시각·일정 적용은 별도 승인 전 저장하지 않는다.
- 허용된 11개 행동만 엄격한 자료형·범위 검사를 거쳐 실행한다. 한 턴 6단계, 전체 45초를 제한한다.
- 여러 도구의 업무 변경을 임시 상태에서 계산하고 최종 버전 검사 후 한 번 저장한다. 후속 실패는 해당 턴의 업무 변경을 취소한다.
- 세션별 요청 ID로 중복 쓰기를 막고 오래된 승인·다른 상담의 승인을 거부한다. 수동 도구 변경은 기존 승인 요청을 만료시킨다.
- 대화 60개 메시지·20턴을 표시용으로 보관하고 요청 식별자 장부는 200개 한도에서 추가 대화를 중단한다. 마지막 승인 슬롯을 남긴다.
- 실제 모델 오류와 실거래 오류를 다른 모드의 성공으로 대체하지 않는다. 개발 플래너가 코드와 도구 연결을 검증하는 것이지 Zoro 성능을 검증하는 것은 아니다.

대화 계약은 `CONTRACT_STAGE6.md`, 20개 실행 평가는 `AGENT_EVALUATION.md`, 독립 보안 검토는 `REVIEW_AGENT.md`를 따른다.
