# 검증 기록 — 집의 다음 v0.3.1

기준일: 2026-11-12, 한국 시간. 이번 작업은 사용자 키 설정·실조회 시도와 API 경계·화면·기존 기능의 통합 검증이다. 실제 인증 성공 및 Zoro 모델 성능은 미검증이다.

## 검사 환경과 격리

Linux / Python 3.12.14의 별도 가상환경에서 `requirements-dev.txt`를 사용했다. 전체 검사 프로세스는 `Settings.from_env`에 명시적 가짜 설정과 임시 DB를 공급하고 실제 dotenv 읽기 및 socket 연결을 차단했다. 단위 검사의 성공을 실제 API 성공으로 바꾸지 않았다. 고정 패키지 버전은 requirements 파일을 따른다.

경고 1개는 Starlette TestClient의 httpx 사용 변경 예고다. 기능 실패가 아니다. Node 문법 검사와 Python 컴파일 검사도 통과했다. 새 UI 검사 파일 `tests/ui_transactions_v03.cjs`를 ZIP에 포함하도록 패키징 목록을 보완했다.

## 수정한 문제

1. 인증·쿼터 등 명시적 오류가 무자료 메시지로 가려져 0건 성공이 될 수 있던 처리.
2. 후속 페이지의 남은 거래 수를 넘는 행이나 있어야 할 페이지의 빈 응답.
3. 무자료 헤더와 본문의 실제 행·전체 건수가 모순되는 응답.
4. 게이트웨이의 두 메시지 중 하나에 있던 인증 오류를 무시하는 처리.
5. 전송 DEBUG 로그가 응답 헤더의 비밀값·URL을 출력할 수 있던 경계. 애플리케이션 실행 기록은 유지하고 HTTP 전송 로그를 차단했다.
6. JavaScript 정수 표현 범위를 넘는 금액의 원 단위 손실. 안전 범위를 넘는 행은 명시적인 제외 건수로 처리한다.
7. 조회 조건을 입력 중 바꿔도 포커스를 옮기기 전까지 이전 결과가 보이던 화면. 입력 즉시 결과를 지우고 진행 요청을 취소한다.
8. 검증 보고서에 없던 조회 조건·범위 메타데이터를 추가했다. 유효하지 않은 입력은 복사하지 않는다.

## v0.3.1 Windows 키 입력 변경

사용자 화면에서 설치 완료 후 숨김 키 입력 프롬프트에 머무는 상태를 확인했다. 화면만으로 Windows 입력 정지의 정확한 원인은 확정하지 않았다. 기존 콘솔 `getpass` 입력을 기본 Windows 실행 경로에서 제거하고 Tk 별도 창을 사용한다.

- 별도 입력칸의 붙여넣기 버튼은 기존 값을 교체하므로 연속 클릭으로 키가 중복되지 않는다.
- ● 마스킹과 입력 글자 수를 표시한다. 공통 키 사용을 기본으로 지원한다.
- 파일 저장은 백그라운드 작업으로 처리하고, 실패 시 입력창을 유지해 재시도한다.
- 저장 성공일 때만 실행기가 기존 실제 API 검사 도구로 넘어간다. 취소·저장 실패는 조회하지 않는다.
- GUI 라이브러리가 없으면 설치 안내를 표시하고 종료한다. 문제가 있던 숨김 입력으로 자동 복귀하지 않는다.
- 테스트는 가짜 키·임시 파일 및 GUI 상태 처리 로직을 검증했다. Linux 데스크톱 시험에서는 창 포커스/입력 도구의 제약으로 실제 클릭 시험을 완료하지 못했다. **Windows 실기기와 새 창의 실제 키보드·마우스 동작은 미검증**이다.
- 이 수정 작업에서 실제 키를 재배포하거나 새 국토부 실조회 성공을 주장하지 않았다.

## 실제 API 상태

두 이미지의 키를 작업 환경의 비공개 서버 설정에 반영했다. 최종 CLI 검사에서 매매·전월세 모두 **FAILED / MOLIT_CONNECTION_ERROR**, `both_apis_verified=false`였다. 기본 경로의 이름 해석 실패와 환경 제공 경로의 비인증 연결 시간 초과를 별도로 관찰했다.

자세한 시각·조건·해석은 [LIVE_API_CHECK.md](LIVE_API_CHECK.md)를 따른다. 제공기관의 인증 응답을 받지 못했으므로 실제 금액·면적·계약일·해제 정보의 변환은 합성 응답으로만 검증했다.

## 배포와 남은 범위

ZIP은 키·첨부 이미지·런타임 DB·실행 보고서·가상환경을 포함하지 않는다. 전체 파일을 실제 인증키와 대조하여 키 포함 여부를 검사한다. 다운로드본은 사용자 PC의 키 설정을 대신하지 않는다. 기존 폴더의 .env는 업데이트 성공·실패 시 보존됨을 가짜 키로 검사했다.

남음: 접속 가능한 환경에서 두 API 인증·실데이터 확인, Windows 실기기, Zoro 실행·행동 선택. 큰 일정으로 확장할 때의 탐색량 제한과 검증 보고서의 페이지 메타데이터 중복 확인 등 검토 범위의 한계는 각 REVIEW 문서에 기록했다. 현재 공개 경로의 고정 시연·직접 API 파서 계약을 유지했다.

이 버전은 실제 업체 예약·메시지 발송·공개 배포를 수행하지 않았다.
