# 집의 다음 · Zoro Realty Agent

강남구 아파트 전세를 상담하는 중개사와 고객을 위한 앱입니다. 고객이 꼭 지켜야 할 조건을 정하면 후보를 추리고, 집을 본 뒤 새로 알게 된 사실이나 입주 시간 변경을 같은 상담에서 반영합니다.

**[발표자료 9장](https://docs.google.com/presentation/d/1VPpDth7YF2oiBI0g6eKCIF2ZDJQByB7qyvs8k9Aug9E/edit?slide=id.p1#slide=id.p1) · [실제 앱 시연 녹화 · 1분 2초](https://drive.google.com/file/d/1glDUGIpctpFEOYttOO61-2cBdNl9vSQZ/view) · [실행 로그 3종](submission/README.md)**

Trillion Labs Agent AI Hackathon 2026 · Track 1. 행사에서 NVIDIA Brev L40S로 Zoro-1을 실행했고, 현재 GPU 연결은 종료했습니다. **당시 Zoro가 도구를 선택한 장면은 녹화본에서, 같은 앱의 상담·승인·재검색은 GPU 없이 개발용 규칙 모드에서** 확인할 수 있습니다. 발표자료와 영상은 로그인 없이 볼 수 있습니다.

## 왜 만들었나요?

중개 현장에서 “현관까지 계단 없이 들어갈 수 있나요?”라는 질문은 추천 결과를 바꿉니다. 보증금과 면적이 맞는 집도 현관 앞에 계단이 한 칸 있으면 그 고객에게 보여드릴 이유가 없어집니다. 입주 날 열쇠를 세 시에 받기로 바뀌면 오전에 잡아 둔 청소와 이사도 다시 검토해야 합니다.

중개사가 확인 내용을 한 번 기록하면 고객이 **어떤 집이 왜 빠졌는지, 무엇을 더 확인해야 하는지, 어떤 일정이 가능한지** 그 자리에서 함께 볼 수 있도록 만들었습니다. Zoro-1은 다음에 실행할 도구를 고릅니다. 앱은 도구 결과로 후보와 일정을 계산하고, 저장할 변경이 있을 때 사용자에게 먼저 보여줍니다.

## 중개사와 고객이 함께 써보는 순서

| 상담 장면 | 고객과 중개사가 화면에서 확인하는 것 |
| --- | --- |
| 고객이 “보증금 10억 이하, 전용 75㎡ 이상, 계단 없는 출입 필수”라고 요청합니다. | 조건을 검토하고 승인하면 가상 매물 20개가 충족 6개, 확인 필요 3개, 제외 11개로 나뉩니다. |
| 중개사가 방문 뒤 “L001은 무계단 접근이 불가능합니다”라고 입력합니다. | 제안된 현장 기록을 승인하면 L001이 후보에서 빠집니다. 충족은 6개, 확인 필요는 2개, 제외는 12개가 됩니다. |
| 고객이 “열쇠를 오후 3시에 받아요”라고 알립니다. | 새 입주 시각을 승인하면 앱이 기존 청소·이사 일정의 충돌 2건을 찾아 대안 3개를 제시합니다. 대안을 골라 별도로 승인해야 내부 일정에 반영됩니다. |

추천 매물과 업체 시간표는 가상입니다. 일정 변경은 상담 기록에만 적용됩니다. 국토교통부 매매·전월세 API를 별도로 설정하면 **이미 신고된 계약**을 참고할 수 있습니다.

## 앱 실행하기

- **브라우저에서 체험** — GitHub에 로그인해 Codespace를 만들면 앱이 시작됩니다. 새 탭이 열리지 않으면 **Ports → 8000 → 브라우저에서 열기**를 누르세요. [GitHub Codespaces에서 앱 열기](https://codespaces.new/johnnyscalper/zoro-realty-agent)
- **Windows에서 체험** — Python 3.11 이상이 설치된 PC에서 저장소의 **Code → Download ZIP**을 누르고 압축을 풉니다. 폴더 안의 `START_WINDOWS.cmd`를 더블클릭하고 **키 없이 예시 자료로 먼저 시작**을 선택하세요. 첫 설치에는 인터넷이 필요합니다. [Windows 실행 안내](START_HERE_KO.md)
- **macOS·Linux** — Python 3.11 이상에서 프로젝트 폴더의 `sh START_MAC_LINUX.sh`를 실행한 뒤 브라우저로 `http://127.0.0.1:8000`을 엽니다.

처음에는 **상담 에이전트 → 01 · 조건으로 찾기 → 보내기 → 변경 승인 · 계속**을 누르세요. 같은 상담에서 **02 · 확인 결과 반영**을 실행하면 조건을 유지하면서 추천이 어떻게 바뀌는지 볼 수 있습니다.

## 앞으로 보완할 점

1. **매물이 아직 거래 가능한지 보여주겠습니다.** 제공에 동의한 중개사의 매물을 연결해 거래 가능 여부와 마지막 확인 시각을 함께 표시하겠습니다.
2. **고객이 추천 근거를 직접 확인할 수 있게 하겠습니다.** 국토부의 과거 계약 금액과 현재 호가를 구분하고, 무계단 출입처럼 현장에서 추가로 확인해야 할 조건에는 확인 일자와 근거를 붙이겠습니다.
3. **Zoro 실험을 20개 상담으로 넓히겠습니다.** 필수 조건을 위반한 매물이 다시 추천된 횟수, 사용자 승인 없이 저장된 변경 건수, 일정 대안에 남은 충돌 건수를 측정하겠습니다.

### 로컬 설치와 기존 상담 기록

전체 통합본은 기존 폴더와 별도로 새 폴더에서 실행합니다. 기존 `.env`와 `.runtime`을 삭제하지 않습니다. 키 가져오기는 국토부 키만 복사하며 기존 상담 기록·GPU 주소·코드를 옮기지 않습니다. 새 앱은 `.runtime/realty.sqlite3`에 새 상담을 저장합니다. 상담 ID는 같은 DB에서만 사용할 수 있습니다. 기존 폴더 안에서 업데이트하는 방법도 계속 지원하지만 이번 전체본 실행에 필수는 아닙니다.

## 상담 화면

첫 화면은 `상담 에이전트`입니다. `개발용 규칙 모드`와 `가상 응답 예시`로 시작합니다.

1. `01 · 조건으로 찾기`를 누르고 보내면 해석한 조건을 보여줍니다. **변경 승인 · 계속** 후 후보와 필요한 확인 작업을 만듭니다.
2. `02 · 확인 결과 반영`은 L001의 무계단 접근 불가라는 가상 현장 결과를 제안합니다. 승인하면 후보를 다시 검사합니다.
3. `03 · 일정 다시 짜기`를 보내고 승인하면 오후 3시 입주 가능으로 바꾸고 충돌·대안을 계산합니다. 대안 선택 버튼은 요청 문장을 입력합니다. 보내기와 최종 승인을 거쳐 내부 일정에 반영합니다.
4. `04 · 과거 자료 조회`는 2026년 10월 강남구 전월세 기록을 조회합니다. 실제 자료는 **실거래 데이터 → 국토부 실제 조회**를 선택한 뒤 요청하세요.

GPU 없이 동작하는 개발용 규칙은 제한된 한국어 표현을 처리합니다. 모호한 값, 지원하지 않는 필수 조건, 단순 확인 요청은 질문으로 돌려보냅니다. 예산을 추정하거나 필수 조건을 조용히 완화하지 않습니다. 긴 자유 문장이 잘 해석되지 않으면 예시 버튼 또는 기존 `실행실`의 구조화된 입력을 사용하세요.

새로고침 후 `세션 이어가기 → 불러오기`로 대화를 복원합니다. 같은 세션의 세부 도구 보기로 기존 실행실을 열 수 있습니다. 수동 변경 후에는 상담의 새로고침으로 최신 버전을 불러오세요. 오래된 승인·일정 대안과 중복 변경은 서버에서 차단합니다.

## 국토부 연결 상태

2026-11-12 Windows PC에서 두 API 응답이 화면에 표시된 것을 참가자가 확인했습니다. 제출용 Check 5는 국토부 API를 호출하지 않았습니다. [상세 기록](docs/LIVE_API_CHECK.md)을 참고하세요.

이미 작동하는 키는 그대로 사용하세요. 새 PC에서만 `CONFIGURE_API_KEYS_WINDOWS.cmd`의 별도 입력창으로 키를 저장합니다. 두 서비스에 같은 키를 사용할 수 있지만 활용승인은 각각 필요합니다. 키 저장 후 서버를 다시 시작하세요. 상단 배지는 설정 여부이며, 실조회 성공 증거는 실제 응답/검사 보고서입니다.

기존 `실거래 조회` 탭의 페이지 조회를 유지합니다. 상담 도구는 참고 근거로 최대 2페이지, 페이지당 100건을 읽고 최대 10건을 표시합니다. 취소된 매매는 제외하고, 부분 조회·누락·해제 여부 미확인을 명시합니다. 실패를 가상 자료로 바꾸지 않습니다.

## 설정

서버만 `.env`를 읽으며 환경변수가 우선합니다. 실제 키·서버 비밀값은 채팅에 입력하지 않습니다.

| 변수 | 용도 |
| --- | --- |
| MOLIT_TRADE_API_KEY / MOLIT_RENT_API_KEY | 매매·전월세 인증키 |
| MOLIT_API_KEY | 개별 키가 비어 있을 때 공통 키 |
| MOLIT_TIMEOUT_SECONDS | 국토부 대기 제한 1~30초, 기본 10 |
| ZORO_BASE_URL | 제공받은 추론 서버 주소 |
| ZORO_MODEL | 제공받은 정확한 모델 ID, 기본값 없음 |
| ZORO_API_KEY | 서버가 요구하는 경우만 설정 |
| ZORO_TIMEOUT_SECONDS | 모델 요청 제한 1~30초, 기본 15 |
| STATE_DB_PATH | 선택: 상담 DB 경로 |
| APP_HOST / APP_PORT | 기본 127.0.0.1 / 8000 |

현재 Zoro 어댑터는 **OpenAI Chat Completions 경로**를 사용합니다. v0.4.1에서 공식 decision/chat 서버 소스를 확인하고 행동 선택 요청에 `enable_thinking=false`, `temperature=0`을 지정했습니다. 행사 L40S에서 측정한 세 시나리오의 동작과 소요 시간은 [Check 5 기록](submission/README.md)에서 볼 수 있습니다. 모델 오류를 개발 모드로 자동 대체하지 않습니다. 구체적인 설치와 연결 순서는 [ZORO_GPU_QUICKSTART.md](docs/ZORO_GPU_QUICKSTART.md)에 있습니다.

```bash
python -m pytest -q
python scripts/evaluate_agent.py

```

화면 검사 전체 재현에는 Node도 필요합니다. 평가 스크립트는 실제 키·네트워크·개인 DB를 사용하지 않고 20개 HTTP 시나리오를 검사합니다. 테스트 개수와 20개 시나리오 성적을 중복 합산하지 않습니다. [검증 범위와 결과](docs/VERIFICATION.md), [평가 안내](docs/AGENT_EVALUATION.md)를 참고하세요.

기존 API를 유지하며 `GET /api/agent/status`, `POST /api/sessions/{id}/chat`, `POST /api/sessions/{id}/chat/confirm`을 추가했습니다. 정확한 계약은 [CONTRACT_STAGE6.md](CONTRACT_STAGE6.md), 기존 수동 도구는 [CONTRACT_STAGE5.md](CONTRACT_STAGE5.md)를 따릅니다.

서버는 허용된 행동만 실행하며 한 턴 6단계·전체 45초 제한을 둡니다. 변경은 승인 후 하나의 트랜잭션으로 저장하고 실패 시 해당 턴의 업무 변경을 되돌립니다. `.env`, DB, 실행 보고서, 가상환경, 모델 파일은 배포 ZIP에 넣지 않습니다.
