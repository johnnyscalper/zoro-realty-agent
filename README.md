### 현재 구현 범위

- **추천 후보 20개·현장 확인 자료·업체 시간표는 가상 데이터**입니다.
- 국토부 데이터는 **신고된 과거 계약**입니다. 현재 거래 가능한 매물 추천과는 별도입니다.
- Zoro를 연결하면 다음 행동을 선택하도록 구성했습니다. 최종 상담 문장은 검증된 도구 결과를 바탕으로 앱이 구성합니다.
- 실제 업체 예약·연락·계약·결제는 수행하지 않습니다. 로컬 실행용이며 웹에 서비스로 배포한 상태는 아닙니다.

## 바로 실행하기

1. 이 브랜치의 **Code → Download ZIP**을 눌러 내려받고 압축을 풉니다.
2. Python 3.11 이상이 설치된 Windows에서는 `START_WINDOWS.cmd`를 실행합니다.
3. 처음 시작 창에서 **예시 자료 사용**을 선택하면 키나 GPU 없이 시연할 수 있습니다. 처음 설치에는 인터넷이 필요합니다.
4. 브라우저의 `http://127.0.0.1:8000`에서 상담 화면을 엽니다. 실행 창은 열어 두세요.

macOS/Linux에서는 `sh START_MAC_LINUX.sh`를 실행합니다. 자세한 순서는 [START_HERE_KO.md](START_HERE_KO.md)를 참고하세요. 국토부 실조회는 별도 키 설정 후 사용할 수 있습니다. `.env`와 상담 DB는 공개 저장소에 포함하지 않습니다.

## v0.4.3 기본 상담 문장

- 인사 후 보증금을 묻고, 확인 질문과 변경 승인 안내를 친절하게 표시합니다.
- 완료된 도구 결과를 짧은 상담 문장으로 설명하고, 다음에 입력할 수 있는 요청을 안내합니다.
- 후보 수와 미확인 항목, 가상/국토부 자료 출처, 일부 범위 조회, 실제 예약이 아니라는 설명을 유지합니다.
- 별도 모델 호출 없이 개발 모드와 Zoro 모드 모두 같은 결과 설명기를 사용합니다. Zoro는 행동을 선택하며, 최종 설명은 앱의 문장 구성기로 만듭니다. 자유로운 장문 생성이나 실시간 글자 출력은 포함하지 않습니다.

예: `안녕하세요` → `보증금 10억 이하, 75㎡ 이상, 무단차 필수` → **변경 승인 · 계속**. 결과와 확인할 항목을 상담 문장으로 읽을 수 있습니다.

## 기존 핵심 기능

| 항목 | 작동 내용 |

| 2. 기존 도구 통합 | 가상 후보 검색, 내부 확인 요청, 사용자가 확인한 결과 기록, 과거 매매·전월세 참고 조회 |
| 3. 변화 대응 | 확인 결과·계약 상태에 따라 후보 재검사, 입주 지연 충돌 계산, 가상 시간표 내 대안 생성·선택·승인 |
| 4. Zoro 준비·평가 | 별도 모델 어댑터, 엄격한 도구 인수 검사, 제한된 실행 반복, 모드·출처 표시, 20개 HTTP 평가 시나리오 |

현재 추천 후보 20개, 현장 자료와 업체 시간표는 **가상**입니다. 국토부 자료는 신고된 **과거 계약**이며 현재 거래 가능한 매물 목록이 아닙니다. 두 자료를 섞어 현재 매물이나 접근성을 추정하지 않습니다. 일정 적용은 내부 기록이며 실제 예약·업체 연락은 없습니다.

## 실행

Python 3.11 이상이 필요합니다. Windows는 `START_WINDOWS.cmd`, macOS/Linux는 `sh START_MAC_LINUX.sh`를 실행하세요. 공통 실행기는 `python scripts/bootstrap.py`입니다. 처음 설치에는 인터넷이 필요합니다. 기본 주소는 `http://127.0.0.1:8000`이며 실행 창을 유지하세요.

전체 통합본은 기존 폴더와 별도로 새 폴더에서 실행합니다. 기존 `.env`와 `.runtime`을 삭제하지 않습니다. 키 가져오기는 국토부 키만 복사하며 기존 상담 기록·GPU 주소·코드를 옮기지 않습니다. 새 앱은 `.runtime/realty.sqlite3`에 새 상담을 저장합니다. 상담 ID는 같은 DB에서만 사용할 수 있습니다. 기존 폴더 안에서 업데이트하는 방법도 계속 지원하지만 이번 전체본 실행에 필수는 아닙니다.

## 상담 화면

첫 화면은 `상담 에이전트`입니다. `개발용 규칙 모드`와 `가상 응답 예시`로 시작합니다.

1. `01 · 조건으로 찾기`를 누르고 보내면 해석한 조건을 보여줍니다. **변경 승인 · 계속** 후 후보와 필요한 확인 작업을 만듭니다.
2. `02 · 확인 결과 반영`은 L001의 무계단 접근 불가라는 가상 현장 결과를 제안합니다. 승인하면 후보를 다시 검사합니다.
3. `03 · 일정 다시 짜기`를 보내고 승인하면 오후 3시 입주 가능으로 바꾸고 충돌·대안을 계산합니다. 대안 선택 버튼은 요청 문장을 입력합니다. 보내기와 최종 승인을 거쳐 내부 일정에 반영합니다.
4. `04 · 과거 자료 조회`는 2026년 10월 강남구 전월세 기록을 조회합니다. 실제 자료는 **실거래 데이터 → 국토부 실제 조회**를 선택한 뒤 요청하세요.

일반 대화 모델을 연결하기 전의 개발 규칙은 제한된 한국어 표현을 처리합니다. 모호한 값, 지원하지 않는 필수 조건, 단순 확인 요청은 질문으로 돌려보냅니다. 예산을 추정하거나 필수 조건을 조용히 완화하지 않습니다. 긴 자유 문장이 잘 해석되지 않으면 예시 버튼 또는 기존 `실행실`의 구조화된 입력을 사용하세요.

새로고침 후 `세션 이어가기 → 불러오기`로 대화를 복원합니다. 같은 세션의 세부 도구 보기로 기존 실행실을 열 수 있습니다. 수동 변경 후에는 상담의 새로고침으로 최신 버전을 불러오세요. 오래된 승인·일정 대안과 중복 변경은 서버에서 차단합니다.

## 국토부 연결 상태

사용자는 2026-11-12 자신의 Windows PC에서 매매·전월세 자료가 모두 정상 표시된다고 확인했습니다. 이것은 사용자 환경의 성공 보고입니다. 이 작업 환경의 이전 인증 조회는 네트워크 연결 단계에서 실패했고, 이번 오프라인 검사로 그 기록을 성공으로 바꾸지 않았습니다. [상세 기록](docs/LIVE_API_CHECK.md)을 참고하세요.

이미 작동하는 키는 그대로 사용하세요. 새 PC에서만 `CONFIGURE_API_KEYS_WINDOWS.cmd`의 별도 입력창으로 키를 저장합니다. 두 서비스에 같은 키를 사용할 수 있지만 활용승인은 각각 필요합니다. 키 저장 후 서버를 다시 시작하세요. 상단 배지는 설정 여부이며, 실조회 성공 증거는 실제 응답/검사 보고서입니다.

기존 `실거래 조회` 탭의 페이지 조회를 유지합니다. 상담 도구는 참고 근거로 최대 2페이지, 페이지당 100건을 읽고 최대 10건을 표시합니다. 취소된 매매는 제외하고, 부분 조회·누락·해제 여부 미확인을 명시합니다. 실패를 가상 자료로 바꾸지 않습니다.

## 설정

서버만 `.env`를 읽으며 환경변수가 우선합니다. 실제 키·서버 비밀값은 채팅에 입력하지 않습니다.

| 변수 | 용도 |
| --- | --- |
| MOLIT_TRADE_API_KEY / MOLIT_RENT_API_KEY | 매매·전월세 인증키 |
| MOLIT_API_KEY | 개별 키가 비어 있을 때 공통 키 |
| MOLIT_TIMEOUT_SECONDS | 국토부 대기 제한 1~30초, 기본 10 |
| ZORO_BASE_URL | 제공받은 추론 서버 주소 |
| ZORO_MODEL | 제공받은 정확한 모델 ID, 기본값 없음 |
| ZORO_API_KEY | 서버가 요구하는 경우만 설정 |
| ZORO_TIMEOUT_SECONDS | 모델 요청 제한 1~30초, 기본 15 |
| STATE_DB_PATH | 선택: 상담 DB 경로 |
| APP_HOST / APP_PORT | 기본 127.0.0.1 / 8000 |

현재 Zoro 어댑터는 **OpenAI Chat Completions 경로**를 사용합니다. v0.4.1에서 공식 decision/chat 서버 소스를 확인하고 행동 선택 요청에 `enable_thinking=false`, `temperature=0`을 지정했습니다. 행사 L40S에서 측정한 세 시나리오의 동작과 소요 시간은 [Check 5 기록](submission/README.md)에서 볼 수 있습니다. 모델 오류를 개발 모드로 자동 대체하지 않습니다. 구체적인 설치와 연결 순서는 [ZORO_GPU_QUICKSTART.md](docs/ZORO_GPU_QUICKSTART.md)에 있습니다.

로컬 전용 준비본입니다. 서버는 허용된 행동만 실행하며 한 턴 6단계·전체 45초 제한을 둡니다. 변경은 승인 후 하나의 트랜잭션으로 저장하고 실패 시 해당 턴의 업무 변경을 되돌립니다. `.env`, DB, 실행 보고서, 가상환경, 모델 파일은 배포 ZIP에 넣지 않습니다.
